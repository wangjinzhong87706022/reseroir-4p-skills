# Autoresearch v3.0 - 基线测试

## 概述

本目录包含early-warning Skill v5.2.0的基线测试框架，用于测试103个问题（Q1-Q103）。

## 文件清单

| 文件 | 说明 |
|------|------|
| README.md | 本文件 |
| eval-criteria.md | 评估标准（6维度） |
| test-inputs.md | 测试问题（103题） |
| baseline-test-template.md | 基线测试模板 |
| run-baseline-test.md | 测试执行指南 |
| results.json | 测试结果模板 |
| potential-failures.md | 潜在失败点分析 |
| optimization-log.md | 优化日志 |

## 快速开始

### 1. 确认环境
```bash
# 检查数据库连接
mysql -h 127.0.0.1 -P 3306 -u root -p123456aA. powerelf_srm_yml -e "SELECT COUNT(*) FROM ew_info_message"

# 检查Hermes Agent
curl -X POST http://your-hermes-agent-url/api/health
```

### 2. 运行测试
按照 `run-baseline-test.md` 中的指南，对每个问题：
1. 向Hermes Agent发送问题
2. 记录响应
3. 按6维度评估
4. 填写结果

### 3. 记录结果
将结果填入 `results.json` 文件

### 4. 分析失败项
对每个失败问题，记录：
- 失败维度（E1-E6）
- 失败原因
- 优化建议

## 评估维度

| 维度 | 说明 | 满分 |
|------|------|------|
| E1: SQL正确性 | SQL语法是否正确 | 1分 |
| E2: 数据准确性 | 结果是否与预期一致 | 1分 |
| E3: 响应完整性 | 是否包含所有必要信息 | 1分 |
| E4: 格式规范性 | 输出格式是否清晰 | 1分 |
| E5: 性能优化 | 是否使用时间范围和分页 | 1分 |
| E6: 业务准确性 | 是否符合水利业务逻辑 | 1分 |

**每题满分**: 6分
**总满分**: 103 × 6 = 618分

## 优化迭代

### 迭代流程
1. 运行基线测试
2. 分析失败项
3. 优化Skill
4. 重新测试
5. 重复2-4直到达标

### 优化优先级
1. **P0**: 触发词识别、风险评估、预案触发

3. **P2**: 气象预警、告警聚合、趋势预测
4. **P3**: 边界场景

### 目标
- **第一轮基线**: 预计75%
- **优化后目标**: >90%
- **最终目标**: >95%
