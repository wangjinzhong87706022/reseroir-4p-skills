# Ticket 004 — Demo 场景设计：如何让评委快速看懂

## Question

评委看 Demo 视频只有 5-10 分钟。如何设计"汛期暴雨"场景，让评委在短时间内看到多智能体协作的价值？

## 关键约束

- 评委可能不了解水利也不了解 AgentTeams
- 视频时间有限（5-10分钟），不能慢慢解释
- 需要展示：多智能体协作 + 真实水库数据 + 工程完整性

## 候选场景设计

### 方案A：单场景完整链路（推荐）
```
开场（30秒）：桃曲坡水库当前水位 + 气象预警（暴雨橙色预警）
↓（2分钟）
water-forecast：分析降雨预报和来水趋势
↓ TeamLeader 调度
simulation：3套调度方案对比预演
↓ TeamLeader 调度
dispatch-planner：生成推荐方案（含风险提示）
↓ TeamLeader 调度
early-warning：发布黄色预警 + 建议开启泄洪洞
↓（30秒）
TeamLeader 汇总报告：汛限水位786.80m，当前783.50m，预计24h后突破，建议启动调度预案
```

### 方案B：双场景对比
- 场景1（日常）：水位正常，预报+预案，Worker 各跑一次
- 场景2（暴雨）：水位快速上涨，四预链路完整触发

### 方案C：故障注入场景
- 注入"误报"告警，考验 diagnosis Worker 的去噪能力

## 预期答案

**推荐方案A（单场景完整链路）**：
- 理由：场景清晰，逻辑递进，评委容易跟上
- 关键：开头必须用 30 秒交代"这是桃曲坡水库，这是暴雨橙色预警，这是当前水位"
- 亮点：最后 TeamLeader 汇总时，用数字（"水位783.50m，汛限786.80m"）打动评委
