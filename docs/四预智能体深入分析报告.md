## 一、总览：四预智能体在本项目的形态

本项目以 **Hermes + Skill 架构**承载"四预"能力，不是单个智能体，而是 **4 个专业 Skill 组成的能力集群**，由 Hermes 路由器按意图分发：

| 四预环节 | 对应 Skill | 版本 | 一句话职责 |
|---------|-----------|:----:|-----------|
| **预知（预报）** | `forecasting` | v1.0.1 | 降雨预报解读、水库影响估算、多源融合、水位趋势预测、精度评估 |
| **预警** | `early-warning` | v5.2.0 | 告警分析、诊断、风险评估、趋势预测、问答 |
| **预演（方案/推演）** | `plan-generation` | v3.2.1 | 防汛形势评估、调度预案生成、方案对比推荐 |
| **预演（仿真）** | `simulation` | v1.9.3 | 多方案对比预演、敏感性分析、预演报告、模型服务调用 |

**核心特征**：全部 Skill 已接入 **reservoir profile 机制**（`SRM_RESERVOIR_NAME` 环境变量，默认 sancha、桃曲坡 taoqupo），同一套代码天然多水库。桃曲坡已分配 tenant_id=20 并录入现网。

## 二、已实现部分详析

### 2.1 forecasting（预知/预报）— 已实现

**能力矩阵**（SKILL.md v1.0.1）：

| 能力 | 实现方式 | 数据来源 |
|------|---------|---------|
| 降雨预报解读 | 和风168h / 和风30d / NMC 24h / 分区模型 **四源融合** | `query_forecast_data.py`（16函数） |
| 水库影响估算 | 降雨→入库流量→水位影响（LLM 推理，非固定算法） | full_context 一次取全 |
| 多源分歧裁决 | `multi-source-fusion.md` 六步推理框架（可用性→分歧→方向→采信） | fusion_detail / multi_source_overview |
| 水位趋势预测 | 线性外推 / 移动平均 / 指数平滑 | st_rsvr_r |
| 预报精度评估 | MAPE + 合格率 + 置信分级（**gated 机制**：样本<30d 绝不编数字） | `query_forecast_analysis.py` |
| 预警等级判定 | 9 条 IF/ELIF 规则，**阈值零硬编码**（运行时读 full_context） | forecast-rules.md |

**关键设计**：
- ⛔ 输出蓝图三段式：**【依据】(GB/T 22482)** → **【分析】** → **【校验与依据】(安全校验+精度状态)**，结尾段缺失=整题不合格
- ⛔ 数据源隔离铁律：只读 `model_result_files(type=1)` 预报来水过程，**不触发任何模型计算**（那是 plan-generation / simulation 的职责）
- 数据缺失 9 种降级话术（水位 NULL、预报空、精度表空、预报陈旧>6h 等）
- 已完成多轮 autoresearch 优化（autoresearch-forecast-skill，含 3-pass 基线测试、smoke 测试）

## 四、后续规划部分

### 4.1 多 Agent 集群方案评估结论（docs/多Agent集群方案评估与Supervisor落地.md，2026-08-04）

**核心结论**：6 大 Agent 集群的**角色定义本项目已具备**（甚至更细），真正缺的是 **Supervisor 协同编排层**——从"工具箱"到"自动化闭环"的跃迁。

**4 个值得借鉴的点**：

| 借鉴点 | 现状差距 | 价值 |
|--------|---------|:----:|
| ① Supervisor 主管调度+冲突仲裁 | 各 skill 独立，无显式编排，暴雨场景靠人工/单 skill 触发 | ★★★★★ |
| ② 孪生仿真作为决策强制校验 | simulation 有仿真但**没形成"plan-gen 出方案→必须 simulation 校验"的强制闭环** | ★★★★ |
| ③ 状态记忆+断点续跑（Checkpointer） | skill 无状态单轮调用，长历时暴雨（3天）无法接续研判 | ★★★★ |
| ④ 标准化场景闭环（七步流程） | skill 是工具箱，缺场景级流程编排 | ★★★ |

**落地策略**：不新起 LangGraph，在 Hermes + Skill 上加一层 Supervisor skill（场景识别+任务拆解+编排+仲裁+SQLite State），复用现有 10 个 skill 作为工具。

**场景 A（暴雨研判）七步 DAG**：
```
触发: 超限告警 / 人工指令
→ forecasting(雨情水情研判)
→ diagnosis-verification + inspection(工情+设备核查)
→ simulation(多方案洪水推演)
→ plan-generation(生成调度方案，经 simulation 校验)
→ [仲裁](方案 vs 仿真结果一致性，以仿真为准)
→ chatbi(研判报告+值班台账+推送)
```

**三阶段实施路线**：A(1-2周) Supervisor 骨架+单场景闭环 → B(2-4周) 状态记忆+仲裁+多场景 → C(1-2月) HITL+报告归档+推送。

## 六、推荐实施路线（结合本文档与 Supervisor 方案）

## 七、结论

1. **四预智能体的"能力层"已经实现且成熟**——4 个 skill 覆盖预报/预警/预演全部环节，多水库适配完成，桃曲坡领域知识（profile+文档数字化）已齐备。
2. **最大的下一步不是"再建一个智能体"，而是"把已有的编起来"**——Supervisor 协同编排层（跨 skill DAG、全局 State、结果仲裁）是从"工具箱"到"自动化闭环"的关键跃迁，这也是文档明确评估出的最高价值方向。
3. **知识库基建（RAG 向量化 + 结构化数据入库）是前提**——刚完成的全量文档数字化为此提供了现成素材，先验证检索质量、再谈上层智能体。
4. **仿真强制校验应固化为流程刚性**——"先推演后决策"对水利严谨性至关重要，是区别于普通问答智能体的专业壁垒。
