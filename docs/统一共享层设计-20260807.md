# 统一共享层设计（2026-08-07）

> **目的**：解决 SmartTwinRes-skills 各 skill 脚本 `sys.path` / `import` 写法三套并存、`query_utils.py` 本地副本漂移、知识库 `references/` 跨 skill 重复的问题。
>
> **参考**：`/opt/git/water-resources-skills/`（DeerFlow 适配项目，已实现 `bootstrap.py` 三层定位 + `shared/` 共享知识库）。

---

## 一、问题现状

### 1.1 脚本头部三套写法

| 写法 | 出现 skill | 问题 |
|------|-----------|------|
| `sys.path.insert(0, dir(__file__))` + `from query_utils import ...` | forecasting、plan-generation | query_utils 是本地副本，DB 连接/错误处理改动需同步多份 |
| `sys.path.insert(0, repo_root)` + `from lib.db import ...` | simulation、early-warning、diagnosis | 正确，但每个脚本自己算 `repo_root`，无统一入口 |
| `sys.path.insert(0, lib_dir)` + `from lib.paths import ...` | supervisor、test_skills | 最干净，但仅 supervisor 用 |

### 1.2 query_utils.py 副本漂移

- `forecasting/scripts/query_utils.py` 与 `plan-generation/scripts/query_utils.py` 各一份，内容近似但不一致。
- simulation / early-warning / diagnosis 无 query_utils，直接 `from lib.db import`。
- 改 DB 连接逻辑需改 N 处，且容易漏改导致行为不一致。

### 1.3 知识库 references/ 跨 skill 重复

各 skill `references/` 下均有 `table-schema.md`、`knowledge-base.md`、`sql-templates.md`，内容大量重叠。无统一 `shared/` 目录。

## 二、设计方案

### 2.1 三层目录定位（仿 water-resources bootstrap.py）

引入环境变量 `SRM_SKILLS_ROOT`（部署契约，指向仓库根），配合候选根兜底：

```
SRM_SKILLS_ROOT env（部署契约，主路径）
  → 候选根兜底（_KNOWN_ROOTS 元组遍历，dev 便利）
  → RuntimeError（找不到 lib/db.py 时）
```

**为什么需要 env 变量**：Hermes/LLM 暂存脚本里 `__file__` 不可靠（参考项目踩过此坑），必须用 env 变量定位共享层。

**为什么保留候选根兜底**：dev 环境未设 env 时仍能跑，降低上手门槛。

### 2.2 lib/bootstrap.py 实现

```python
"""SmartTwinRes-skills 三层定位器。

Priority:
  1. SRM_SKILLS_ROOT env var (deployment contract)       ← 主路径
  2. Candidate-root fallback (dev convenience)            ← 兜底
  3. RuntimeError                                          ← 找不到时
"""
import os
from pathlib import Path

_LIB_MARKER = "db.py"

# 兜底候选根（仅当环境变量未设时遍历）
_KNOWN_ROOTS = (
    "/home/scada/SmartTwinRes-skills",        # 当前部署位置
    "/opt/git/SmartTwinRes-skills",           # 可能的部署位置
    str(Path.home() / "SmartTwinRes-skills"),
)


def locate_root() -> Path:
    """返回仓库根目录（含 lib/db.py）。"""
    r = os.environ.get("SRM_SKILLS_ROOT")
    if r and (Path(r) / "lib" / _LIB_MARKER).exists():
        return Path(r)
    for c in _KNOWN_ROOTS:
        if (Path(c) / "lib" / _LIB_MARKER).exists():
            return Path(c)
    raise RuntimeError(
        "SmartTwinRes lib/ not found. Set SRM_SKILLS_ROOT to the repo root."
    )


def locate_lib() -> Path:
    """返回 lib/ 目录绝对路径。"""
    return locate_root() / "lib"


def locate_shared() -> Path:
    """返回 shared/ 共享知识库目录。"""
    return locate_root() / "shared"
```

### 2.3 标准导入片段（固化到各 SKILL.md）

LLM 运行时生成代码时照抄，杜绝手写 `pymysql.connect` 或硬编码密码：

```python
# 标准导入片段（照抄，禁手写 pymysql.connect / 硬编码密码）
import os, sys
sys.path.insert(0, os.path.join(os.environ['SRM_SKILLS_ROOT'], 'lib'))
from db import execute_query, execute_query_list
from tenant import current_tenant_id
```

离线脚本（`scripts/` 下，`__file__` 可靠）：

```python
import sys
from pathlib import Path
_REPO_ROOT = Path(__file__).resolve().parents[2]  # scripts/x.py → 根
if str(_REPO_ROOT) not in sys.path:
    sys.path.insert(0, str(_REPO_ROOT / "lib"))
from db import execute_query, execute_query_list
from tenant import current_tenant_id
```

### 2.4 query_utils 收口

- 把 `forecasting/scripts/query_utils.py` 与 `plan-generation/scripts/query_utils.py` 的 `unpack`、`execute_query`、`execute_query_list` 等函数合并进 `lib/db.py`（已有 `execute_query`，只需补齐 `unpack` 等）。
- 删除 forecasting、plan-generation 的本地 `query_utils.py` 副本。
- 所有脚本统一走 `from db import execute_query, execute_query_list, unpack`。

### 2.5 shared/ 共享知识库

新建 `shared/` 目录，收口跨 skill 重复的文档：

```
shared/
├── sql-safety-rules.md      # SQL 安全规则（SELECT-only、必须有 WHERE/LIMIT）
├── tenant-filtering-rules.md # 租户过滤铁律（AGENTS.md 第 2 条的展开）
├── db-connection.md         # DB 连接标准（SRM_DB_* 命名空间）
└── common-schema/
    └── README.md            # 跨 skill 复用的表结构（占位，后续填充）
```

各 skill 的 `references/` 只保留**本 skill 专属**的知识（如 forecasting 的 `forecast-rules.md`、simulation 的 `simulation-knowledge-base.md`）。

## 五、风险与回退

- **风险**：删除 `query_utils.py` 后，引用它的脚本会 ImportError。
- **缓解**：收口时保留 `lib/db.py` 的 `unpack` / `execute_query` / `execute_query_list` 接口签名不变，仅改 import 路径。
- **回退**：`git checkout <affected files>` 即可恢复，改动均为新增/替换，无破坏性删除。
