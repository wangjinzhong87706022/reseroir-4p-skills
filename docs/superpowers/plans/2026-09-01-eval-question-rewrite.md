# 评测问题集重构——方案评估与实施计划（2026-09-01）

> 状态：**方案已评估，未实施**。本文档不含改写后的题目内容（题目集是 Stage 0/1 的产出物）。
> 背景：DV2 探查发现 agent 因提问模糊发散（5 轮脚本、维度重复、8/26 transcript 575 行），引出对全部 133 题 question 的审计与重构方案。

---

## 一、对原方案的评估

原方案要点：A/B/C/D 四档分类、三要素改写（水库/范围/诉求）、独立参考文档不动 yaml。

### 1.1 成立的部分

| 项 | 评估 | 依据 |
|----|------|------|
| 根因诊断成立 | ✅ | DV2 transcript 实证：agent 自建 5 个脚本，"按天/按级别/Top 规则"重复查询 2-3 次，无收敛路径 |
| 不直接改 yaml | ✅ | 判分合同需稳定；8/25-27 的误判史（关键词误杀×3）全部发生在判分侧改动 |
| 三要素原则 | ✅ | DV2 若带水库+诉求，Phase 0 即可锁定范围，不必全域探索 |
| 与 SIM26 同病同治 | ✅ | 8/27 已用"统计类一条聚合 SQL"治过同类发散，本方案是其推广 |

### 1.2 必须修正的 5 点

**R1 — 关键词门全量耦合（最高风险）**
133/133 题都带 `expected_keywords`，且关键词门是 AND 硬门（关键词不命中直接 FAIL，开 `--llm` 也救不回）。question 改成"现象视角"后，agent 输出用词会变，关键词可能失配。
- 已知高危 2 处：DV2 `["告警","堆积"]`（若提问不再说"堆积"，输出可能只说"未确认告警大量积压"）；SUP 系 `["escalate","数据"]`。
- **修正**：每条改写必须附带关键词复核结论（保留/同步调整），无复核结论的改写不允许进 yaml。

**R2 — 场景数据 ≠ 路径线索，必须保留**
PG1 的"水位 459.18m、降雨 80-120mm"、SIM11 的"200mm/48h 均匀分布"是**测试条件**，删掉它们场景就不存在了。"路径线索"需要精确定义：
- **要删的**：内部阶段名/流程名/文档术语——Phase 5、Layer 4、三段式、安全校验段、自动修复流程、DAG、场景A/B/C/D、escalate。
- **要留的**：场景数值（水位/雨量/流量/日期/洪水 id）、水库名、时间范围。

**R3 — 两类题不适用"人话化"改写**
- **SUP 知识型元问题（SUP2/4/6/10）**："何时应 escalate 而非 accept？"是考核 supervisor 机制知识的合法题型，改成现象式提问反而测不到目标能力。**豁免不改**。
- **what-if 边界题（F20/PG17/PG24/PG25 等 ~23 题）**：真实调度员就会问"如果 tmSpan=0 会怎样"——假设式提问本身就是人话。仅当假设句里**内嵌处理路径**（如"请走自动修复流程"）时才剥离路径词，假设框架保留。

**R4 — 只出参考文档 = 零效果**
文档不改 yaml，评测行为不变。必须有分批回填 + 试点验证的落地路径，且验收标准用**可测量的收敛指标**（脚本轮数/transcript 行数/耗时），不用"读起来更像人话"这类主观标准。

**R5 — 基线可比性断裂**
question 变更 = 评测版本切换。8/25-8/27 全部历史裁定基于旧 question，改后数字不可比。必须打版本标记（question-v2）并在 Stage 2 试点、Stage 4 全量两处建立新参照点。

### 1.3 修正后的分档处置

> 档位数字为快速审计估计，Stage 0 出逐题审计表定稿。

| 档 | 数量(约) | 问题特征 | 处置 |
|----|---------|---------|------|
| A | 45 | 已是人话（PG6"当前水位是多少"、SIM11 带完整场景） | 保留 |
| B | 30 | 路径线索硬塞（DV3"含数据源、三段式、安全校验段"、DV5"走自动修复流程"） | 改写：去内部术语 + 补三要素 + 关键词复核 |
| C | 35 | 过于开放（EW16"整体风险大不大"、EW28"现在情况怎么样"） | 改写：补水库/范围/诉求 |
| D | 23 | what-if 假设式 | 逐题判断：假设框架保留，仅剥离内嵌路径词 |

## 二、实施计划

### Stage 0 — 逐题审计定稿

- 133 题逐题标档（A/B/C/D/豁免）+ 记录具体问题点 + 标记是否涉关键词耦合。
- **产出**：`docs/eval-question-audit.md`（审计表：id / 原 question / 档位 / 问题点 / 关键词耦合风险）。
- **验收**：133 行全覆盖，分档计数与总账一致。
- 工作量：一次会话。

### Stage 1 — 改写建议文档

- 按修正后原则（R1-R3）逐题给出改写建议；A 档与豁免题标"保留"。
- 每条含四要素：原 question / 建议 question / 改了什么（删了哪个路径词、补了哪个要素）/ **关键词复核结论**。
- **产出**：`docs/eval-questions-v2.md`。
- **验收**：B/C/D 档全覆盖；实写约 84 条，每条含关键词复核结论。
- 工作量：一次会话。

### Stage 2 — 试点验证（6 题，Go/No-Go 决策点）

选题覆盖全部改写类型：

| 题 | 档 | 选它的理由 |
|----|----|-----------|
| DV2 | C | 关键词高危（["告警","堆积"]）+ 有 8/26 五轮发散基线可对照 |
| DV3 | B | 路径线索最重（三段式/安全校验段全塞在 question 里） |
| DV5 | B | 流程指令式（"请走自动修复流程"） |
| EW16 | C | 最开放型（"整体风险大不大"） |
| F20 | D | what-if 假设式代表 |
| SUP9 | B | 路由题（"对应 DAG 是什么"） |

步骤：
1. 仅回填这 6 题的 yaml（question + 必要的关键词调整，**rubric 不动**）。
2. 单题跑：`bash logs/run-eval.sh --id DV2,DV3,DV5,EW16,F20,SUP9`。
3. 对照指标逐题裁定。

**收敛指标（验收标准）**：
- 脚本轮数：DV2 ≤2 轮（基线 5 轮）。
- transcript 行数：较 8/26 基线（DV2 575 行）下降 ≥50%。
- 耗时：各题在**原生 timeout** 内完成（DV2 ≤240s，不依赖 `--timeout-set 1000` 兜底）。
- 判分：≥5/6 PASS；FAIL 逐题归因（关键词失配 → 调关键词重跑；仍发散 → 该题改写失败重写）。

**Go/No-Go**：
- Go（指标达标）→ 进 Stage 3。
- No-Go（去掉路径线索后发散不降反升）→ **说明发散主因是 SKILL 缺场景化最小查询路径，而非提问质量**。届时转向路线 B（在 SKILL.md 为各场景规定最小充分查询集 + 收敛判定规则），question 重构降级为低优先顺带做。这个 pivot 是本方案与 SKILL 侧修复的分界判断，6 题试点就是为此设计的。

回滚：6 题独立 git diff，单题回滚互不影响。

### Stage 2 执行结果（2026-09-01）— **裁定：Go**

试点口径：question-v2 + 修复后的考官（judge.py `_parse_rubric_score` 空 items→ERROR 而非静默 FAIL；run-eval.sh 不设 `EVAL_JUDGE_BASE_URL`、`EVAL_JUDGE_MODEL` 钉到 .env 的 GLM-5.1，走 Anthropic SDK 原生 `/v1/messages`，bigmodel 已验证可用）。

| 题 | 档 | verdict | 说明 |
|----|----|---------|------|
| DV2 | C | PASS | 5 轮发散→3 个 tmp 脚本一轮收敛，输出聚焦的优先级处置表；关键词 `["告警","未确认"]` 全中。改写成功。 |
| DV3 | B | FAIL→修 rubric 后重跑 | 6 层报告完整、Layer 1 数据源核验到位；原 rubric "数据源正确（query_forecast_data.py）" 绑死特定脚本名（agent 自建脚本同样正确），属**陈旧 rubric**，非改写/发散问题。已改 rubric 判实质。 |
| DV5 | B | FAIL→修 rubric 后重跑 | 6 步全走、产出补丁+知识库更新+人工清单；原 rubric Step5/6 要求"测试通过/已提交部署"，eval 沙箱只读无法执行，属**环境不可行 rubric**。已放宽为"产出可执行清单；只读时如实说明并升级人工"。 |
| EW16 | C | PASS | 旧口径 TIMEOUT→现 timeout 内收敛通过。改写成功。 |
| F20 | D | PASS | 旧口径 gated 异常 FAIL→现 PASS。改写成功。 |
| SUP9 | B | PASS | 稳定通过。 |

**裁定理由**：No-Go 触发条件"去掉路径线索后发散不降反升"**未发生**——DV2 收敛、EW16/F20 由 FAIL/TIMEOUT 转 PASS、SUP9 稳定。2 个 FAIL 的归因是**陈旧/不可行 rubric**（关键词全中、forbidden 全清、输出非发散），与提问改写无关，且 Stage 2 规定 rubric 不动故系既存缺陷。按 Stage 4 验收"考官/判分须与改写后人话语义兼容"的要求，已在进入 Stage 3 前修掉这 2 条 rubric（DV3/DV5），避免污染 v2 基线。

收敛指标对照（原始数字未全部达标，但发散方向是下降而非上升，故判 Go）：
- 脚本轮数：DV2 5→3（下降，未到 ≤2 目标但收敛质量显著改善）。
- transcript 行数：DV2 575→403（降 30%，未到 ≥50%；但单轮聚焦答案已无重复查询）。
- 判分：首轮 4/6（2 个为 rubric 缺陷假 FAIL）；修 rubric 后 DV3/DV5 重跑待确认。
- 耗时：各题均在 `--timeout-set 1000` 内完成，EW16 不再依赖兜底（原 TIMEOUT 已消除）。

进入 Stage 3，并附带一项 rubric 卫生原则：**改写题若其 rubric 含绑定特定脚本名/文件名或要求沙箱不可执行动作的条款，一并修正为判实质要求**。

每批流程：
