## 五、关键发现

### ✅ 优势

1. **数据查询能力出色**: Agent 能正确调用 `query_plan_data.py` 和 `query_plan_analysis.py` 脚本获取实际数据，几乎所有回答都基于真实DB数据
2. **安全约束严格遵守**: 所有方案均未超过汛限水位和安全泄量，Q35超汛限场景正确判断为"一级应急响应"
3. **输出结构规范**: 10/10 输出包含完整的形势判断+方案推荐+风险提示
4. **多方案生成正确**: Q4 和 Q40 成功生成3组对比方案，含参数对比表
5. **历史数据利用充分**: Q19 精确匹配了5条历史洪水，Q30 分析了11条历史预案的趋势

### ⚠️ 不足

1. **E5 历史引用覆盖率偏低 (66.7%)**: 部分题型（形势研判Q14、调度决策Q24、应急响应Q35）缺少历史预案/洪水的明确引用
2. **E3 法规引用不够规范 (80%)**: 部分回答虽运用了专业知识，但未明确引用法规条文（如《防洪法》第X条、SL标准编号等）
3. **Q14 数据偏差**: 防汛形势评估查询到了其他流域的河道水位数据（古运河、邗沟等），而非三岔水库本身的水情数据，导致评估偏移
4. **执行稳定性**: Q1 耗时 3m58s 且有18次 tool calls（含多次 error retry），而同类问题 Q4 仅 1m13s/7次 calls，效率差异大

### ❌ 风险点

1. **模型未校准**: SKILL.md 引用了新安江模型(XAJ)、调度优化、洪水演进三个模型服务，但测试中均未调用。模型参数未校准，实际调度计算可能不准确
2. **Q14 场景识别偏差**: 当问题同时涉及"防汛形势评估"和"气象预警"时，Agent 加载了 water-warning、water-situation、rainfall 等多个 skill，导致查询范围扩大到全流域而非三岔水库
3. **早期预案参数缺失**: Q30 分析指出 #709、#714、#717 等早期预案缺少 targetWaterLevel 等关键字段

## 六、改进建议

### 高优先级

1. **SKILL.md 增加历史引用指令**: 在"决策路由"表中为"形势研判"和"调度决策"类别增加 `historical_plans` 查询步骤
2. **SKILL.md 增加法规引用模板**: 在知识参考部分增加标准引用格式：`依据《防洪法》第X条 / SL XXX-XXXX 标准`
3. **修复 Q14 场景路由**: 在 SKILL.md 中明确"防汛形势评估"应限定查询三岔水库（st_rsvr_r 表 + st_rsvr_rfs_d 表）

### 中优先级

4. **减少 tool call retry**: 优化 query 脚本的 Python 环境检测，避免多次 error retry
5. **统一执行效率**: 建议所有数据查询类场景优先使用 `--type full_context`，减少多步查询

### 低优先级

6. **Q33 知识问答优化**: 对纯知识问答类问题，跳过 E1/E2/E4/E5 标准，仅评估 E3/E6
7. **模型服务集成**: 校准新安江模型参数后，在预案生成场景中调用模型进行定量计算
