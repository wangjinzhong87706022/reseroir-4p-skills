## 二、实际执行风险分析

### 风险1：LLM 可能忽略知识库检索指令

**问题**：SKILL.md 要求"遇到调度参数选择时，必须先读取 dispatch-rules.md"，但 LLM 可能直接凭记忆回答。

**影响**：参数推荐不符合规范要求。

**缓解措施**：
- 在 SKILL.md 中强化指令："不要凭记忆回答，必须先读取知识文件"
- 在 eval 标准中增加"是否实际读取了知识文件"的检查

### 风险2：数据库查询可能返回意外结果

**问题**：水位为 NULL、降雨预报为空、历史预案为空等边界情况。

**影响**：LLM 可能基于空数据做出错误判断。

**缓解措施**：
- 查询脚本已修复 NULL 值过滤
- SKILL.md 中应增加"数据缺失时的降级策略"

### 风险3：模型计算可能失败

**问题**：新安江模型参数未校准，可能产生不合理的洪峰值。

**影响**：预演结果不准确，误导决策。

**缓解措施**：
- 模型参数需要用历史数据率定
- SKILL.md 中应增加"模型结果合理性检查"

### 风险4：安全约束可能被绕过

**问题**：LLM 推荐的参数可能超过汛限水位或安全泄量。

**影响**：生成危险的调度方案。

**缓解措施**：
- SKILL.md 中已有安全约束声明
- 后端 verify 接口进行二次校验
- HITL 人工确认环节

### 风险5：多方案对比可能不充分

**问题**：LLM 可能只生成 1 个方案而非要求的 3 个。

**影响**：无法进行多方案对比择优。

**缓解措施**：
- SKILL.md 中明确要求"生成 3 组参数方案"
- eval 标准中检查方案数量

## 三、SKILL.md 改进建议

### 建议1：增加数据缺失降级策略

```markdown
## 数据缺失处理

当查询返回空数据时：
- 水位为 NULL → 提示"当前水位数据不可用"，不生成预案
- 降雨预报为空 → 使用历史平均降雨量作为参考
- 历史预案为空 → 跳过历史参考，仅用配置中心参数
- 气象预警为空 → 视为无预警，正常调度
```

### 建议2：强化知识库检索指令

```markdown
## 知识库检索（必须执行）

⚠️ 重要：不要凭记忆回答！必须先读取知识文件再回答。

判断流程：
1. 用户提问
2. 判断问题类型
3. 读取对应知识文件（必须！）
4. 结合实时数据
5. 生成回答
```

### 建议3：增加模型结果合理性检查

```markdown
## 模型结果检查

计算完成后，检查以下指标：
- 洪峰流量是否在合理范围（0-10000 m³/s）
- 水位是否在库容曲线范围内（420-468m）
- 削峰率是否在 0-100% 之间
- 如异常，提示"模型计算结果异常，请检查输入数据"
```

### 建议4：增加多方案生成强制指令

```markdown
## 多方案生成（必须执行）

⚠️ 重要：必须生成 3 组方案，不能只生成 1 个。

方案模板：
- 方案A：防洪优先（schedulingTarget=0）
- 方案B：综合平衡（schedulingTarget=2）
- 方案C：兴利保供（schedulingTarget=1）

如果用户明确只要 1 个方案，仍然生成 3 个但标注推荐。
```

### 建议5：增加 HITL 强制指令

```markdown
## HITL 确认（必须执行）

⚠️ 重要：以下操作必须经人工确认才能执行：

1. 保存为预案 → 必须用户确认
2. 水位超过汛限的方案 → 必须标注风险
3. 下泄超过安全泄量的方案 → 必须标注风险
4. 紧急调度决策 → 必须通知相关人员
```
