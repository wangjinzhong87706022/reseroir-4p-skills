## 二、实验记录（5 个关键实验）

### Exp 0 — baseline（v1.0 + mimo 模型）
- **得分**：32/48 = 66.7%（12 题）
- **状态**：基线
- **薄弱点**：E2 安全约束 42%、E4 知识引用 33%

### Exp 1 — 模型切换（v1.1 + 讯飞 Qwen）
- **得分**：36/48 = 75.0%
- **改动**：mimo-v2.5-pro → 讯飞 Qwen（因 mimo 配额耗尽 HTTP 429）
- **效果**：E2 大幅提升（42%→83%），验证 v1.1 安全约束规范有效
- **新问题**：E4 反而下降（33%→17%），说明 v1.1 的 E4"软指令"对 Qwen 不够强

### Exp 2-3 — discard（v1.2/v1.3 强制 E4 引用）
- **得分**：未达预期，丢弃
- **改动**：把 E4 从"建议"改为"必须"，加法规标准库
- **失败原因**：Qwen 模型沉浸分析后忽略中后部指令，>3 题无效
- **教训**：纯"强制"文字指令对中等指令遵循度的模型效果有限

### Exp 4 — keep ✅（v1.4 分级引用策略）
- **得分**：50/60 = 83.3%（15 题，剔除 2 个 stream 错误）
- **改动**：E4 改为**分级**（A 类安全/评估/报告必须引用、B 类计算建议引用、C 类查询无需）
- **效果**：E4 从 17%→60%，核心目标达成
- **关键洞察**：差异化要求比"一刀切强制"更有效，模型负担更小

### Exp 5d — keep ✅✅ 重大突破（v1.8 输出蓝图+防卡死+鲁棒运行器）
- **得分**：61/68 = 89.7%（17 题全跑通，0 失败）
- **三项改动**：
  1. **输出蓝图**（v1.6）：开始前锚定 3 段结构（【依据】+【分析】+【校验与依据】）
  2. **防卡死规则**（v1.8）：execute_code 同代码最多 2 次，失败就换方法
  3. **鲁棒运行器**：10s 间隔 + 错误自动重试 2 次 + 跳过已成功
- **效果**：E4 60%→76%，E2 80%→88%，总分 83.3%→89.7%
- **关键成果**：Q24（数据核实）、Q38/Q40/Q44/Q45（报告类 stream stalled）全部修复

### Exp 6 — keep ✅✅ 突破 95%（v1.9 精简模板+顺序铁律）
- **得分**：65/68 = 95.6%
- **三项针对性改动**：
  1. **顺序铁律**（针对 Q40）：文件路径必须放在【校验与依据】之前，不能当结尾
  2. **敏感性分析精简模板**（针对 Q46）：用汇总对比表，禁止逐档详述（避免 token 超限截断）
  3. **历史经验类任务表**（针对 Q56）：明确结尾引用《调度规程》
- **效果**：Q40（2/4→4/4）、Q46（2/4→4/4）修复
- **取舍决策**：
  - Q62（无数据场景）**接受为合理无引用**——问"有没有1000mm洪水"，正确答案是"没有"，否定结论本就没东西可引用，强行塞法规会画蛇添足
  - Q56（历史叙事型）仍 3/4——模型沉浸讲故事忘收尾，属 prompt 优化边界
- **结论**：3/4 失败题修复，总分 89.7%→95.6%

## 三、关键问题与解决方案

### 问题 1：E2 安全约束引用缺失（42%→88%）

**现象**：输出只给数据，不提"汛限水位""下游安全泄量"等安全约束。

**解决**：在 SKILL.md 顶部增加"安全约束分级"表，明确 A/B 类（含水位数据）必须出现"汛限水位"和具体校验。

### 问题 2：E4 知识引用缺失（33%→76%）⭐ 核心优化

**现象**：输出没有引用任何法规标准（防洪法、GB、SL、调度规程）。

**失败的尝试**（Exp 2-3）：
- ❌ 单纯"强制必须引用" → 模型沉浸分析后忽略
- ❌ 只放结尾"法规依据"段落 → 复杂场景被冲淡

**成功的方案**（v1.4 + v1.8 组合）：
1. **分级引用**（A/B/C 类差异化）— 降低决策负担
2. **输出蓝图 3 段结构** — 从开头就锚定【依据】段和结尾【校验与依据】段
3. **法规标准库 + 可复制示例句** — 模型直接抄，不用自己组织语言

### 问题 3：报告类题目 stream stalled（stream 中断）

**现象**：Q38/Q40/Q44/Q45（报告生成题）反复出现 `Stream stalled mid tool-call`。

**根因分析**（重要发现）：
- 表面：API 流中断
- 实际：模型反复 `import pymysql`/`import sys` 失败（execute_code 沙箱偶发不稳定）→ 死循环重试 → 耗尽时间 → 流中断
- **不是限流**，是模型行为问题

**解决**：v1.8 "防卡死规则" — execute_code 同代码最多 2 次，失败立即换方法（改用现成脚本）。

### 问题 4：报告写文件型（内容在文件，对话只有摘要）

**现象**：Q40/Q45 把完整报告写到 `/tmp/xxx.md`，对话里只返回简短摘要，导致评估脚本判定 E2/E4 失败。

**解决**：能力4 增加"⚠️对话回复完整性"要求，明确禁止只给文件路径。

## 五、评估方法

### 评估样本选择
从 98 题测试集中选 17 题，覆盖：
- **6 种能力**：结果解读(3)、虚拟场景(1)、预演报告(3)、敏感性分析(2)、历史经验(2)、多方案对比(3)、业务/综合(3)
- **3 种类型**：正常(10)、异常(3)、边界(4)
- **通过/失败混合**：防止过拟合

### 4 个二元评估标准
| 标准 | 问题 | 判定 |
|------|------|------|
| E1 数据正确性 | 输出是否包含≥3个实际数值（非编造） | 正则匹配 m³/s/m/mm/% |
| E2 安全约束 | 是否引用汛限水位/安全泄量等约束 | 正则匹配安全约束关键词 |
| E3 结构完整 | 是否包含≥3个结构标记 | 正则匹配标题/章节标记 |
| E4 知识引用 | 是否引用≥1条法规标准 | 正则匹配法规/《》书名号 |

最大分 = 4 evals × 17 题 = 68

### 鲁棒测试运行器
```bash
# 核心特性
TIMEOUT_SECS=1200    # 20分钟超时（多方案对比题需要）
INTERVAL=10          # 每题间隔10秒，避免限流
MAX_RETRY=2          # 错误自动重试2次
# 跳过已成功的题，预加载数组避免管道断裂
```

## 六、剩余问题与后续方向

### Exp 6 后剩余 2 个"失败"题（已做取舍）

| Q号 | 失败项 | 处理决策 | 理由 |
|-----|:---:|---------|------|
| Q56 | E4 | ⚠️ 接受（prompt 优化边界） | 历史叙事型任务，模型沉浸讲故事忘收尾，多次优化仍漏；分析质量本身优秀 |
| Q62 | E2 E4 | ✅ 接受为合理无引用 | 无数据场景（"没有1000mm洪水"），否定结论本就没东西可引用，强行塞法规会画蛇添足 |

> **关键判断**：这两个"失败"是评估指标局限，而非 skill 真实缺陷。继续优化会陷入"应试优化"，损害自然度。

### 进阶方向：harness 层优化（已调研）

hermes 支持 `transform_llm_output` hook（见 `hermes_cli/plugins.py` VALID_HOOKS），可做：
1. **输出验证器**：生成后检测 E2/E4 是否齐全，缺失自动补全（解决 Q56 类问题）
2. **stream stalled 自动重试**：检测到错误输出自动 resume（解决偶发的 API 流中断）
3. **评估反馈闭环**：evaluator 实时打分反馈

这是 prompt 优化之外的第二条路径，能解决 prompt 难以根治的"沉浸型任务忘记收尾"问题。

### 边际收益分析（最终）

```
投入产出比：
Exp 1 (模型切换)        +8.3%   高ROI
Exp 4 (分级引用)        +8.3%   高ROI（核心 E4 优化）
Exp 5d (蓝图+防卡死)    +6.4%   中ROI（解决 stream stalled）
Exp 6 (精简+顺序)       +5.9%   中ROI（Q40/Q46 修复）
后续 Exp 7+             预计<2%  低ROI（已逼近 prompt 优化天花板）
```

**结论**：v1.9（95.6%）已接近 prompt 优化天花板，进一步提升应转向 harness hook 方案。
