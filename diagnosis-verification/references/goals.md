# Goal 定义 — 诊断、验证、修复的完成条件

## 1. diagnose Goal

```bash
/goal 完成水位数据异常诊断，满足以下条件：
   
   【证据项】
   1. 8 Phase 全部完成
   2. 根因分类明确（6 类之一）
   3. 证据链完整（[事实] → [推理] → [结论]）
   4. 修复建议可执行（短期止血 + 长期根治）
   5. 知识已沉淀（写入知识库 + 更新监控规则）
   
   【刹车条件】
   - 最多 3 轮
   - 如果连续两轮无新增证据（如未完成 Phase 5 根因分析），停止并说明原因
   - 如果数据库连接失败，立即停止
```

---

## 2. verify Goal

```bash
/goal 完成预报输出验证，满足以下条件：
   
   【证据项】
   1. 6 层验证全部完成
   2. 无 P0 失败
   3. 验证报告包含详细验证记录
   4. 通过/不通过结论明确
   5. 下一步建议清晰
   
   【刹车条件】
   - 最多 2 轮
   - 如果连续两轮出现新的 P0 失败，停止并升级人工
```

---

## 3. auto-fix Goal

```bash
/goal 完成水位数据超时自动修复，满足以下条件：
   
   【证据项】
   1. 诊断报告已解析（8 Phase 完成）
   2. 知识库已查询（匹配度 >50%）
   3. 修复方案已生成（符合 6 类根因的对应模式）
   4. 修复补丁已生成（diff 格式）
   5. 测试已通过（单元 + 集成 + 回归 + 性能）
   6. 代码已提交并部署到预发环境
   
   【刹车条件】
   - 最多 3 轮（测试失败重试）
   - 如果第 3 轮测试仍失败，立即停止并升级人工
   - 如果改动范围超出预期，立即停止
```

---

## 4. 分级证据（可选）

```bash
/goal 完成诊断任务：
   
   【P0 必须满足】
   1. 8 Phase 全部完成
   2. 根因分类明确
   3. 修复建议可执行
   
   【P1 优化项（满足更好，不满足也可通过）】
   4. 知识已沉淀
   5. 监控规则已更新
   
   【刹车】
   最多 3 轮；连续两轮无 P0 进展则停止
```

## Goal 使用说明

### 基本用法

```bash
/goal <任务描述>，满足以下条件：
   <证据项1>
   <证据项2>
   ...
   最多 <N> 轮；<刹车条件>
```

### 与 Skill 配合使用

1. **先加载 Skill**：`@diagnosis-verification/SKILL.md`
2. **再用 Goal**：定义完成条件和刹车
3. **Claude 自动评估**：每轮检查证据是否满足
4. **输出工作单**：每轮尝试过什么、证据在哪里、为什么继续、为什么停
