# verify（验证）— 6 层独立验证详细文档

## Layer 1：数据源验证 🔍

### 目的
验证数据是否来自正确的来源，防止 skill 间数据源混用。

### 验证内容

| Skill | 正确数据源 | 错误数据源 |
|-------|----------|---------|
| forecasting | `query_forecast_data.py` → `st_rsvr_r` | `query_early_warning.py` 或 `st_pptn_r`（河道站） |
| early-warning | `query_early_warning.py` → `ew_info_message` | 其他 skill 的告警表 |
| plan-generation | `query_plan_data.py` → `st_rsvr_r`（tenant 18） | `sl323` 全区域河道站数据 |
| simulation | `query_simulation_data.py` | 其他 skill 数据源 |

### 通过标准
- ✅ 所有数值字段都标注了数据来源
- ✅ 无其他 skill 的数据源混入
- ✅ SQL 查询语句中包含正确的表名和 tenant 过滤

### 失败处理
- ❌ 若发现数据源混用：
  - 立即标记为"数据源错误"
  - 停止后续验证，返回给诊断 Agent 重新修复
  - 记录到知识库

### 典型盲点
- ⚠️ 水位数据来自 `st_pptn_r`（河道站）vs `st_rsvr_r`（水库站）
- ⚠️ 三岔水库 tenant=18 vs sl323 全区域（包含古运河、邗沟等）

## Layer 2：格式规范验证 📝

### 目的
验证输出是否符合三段式要求。

### 验证内容

#### 1. 三段式完整性
- 【依据】段存在（开头）
- 【分析】段存在（中间）
- 【校验与依据】段存在（结尾）

#### 2. 规范引用

| Skill | 必须引用的法规/标准 |
|-------|------------------|
| forecasting | GB/T 22482《水文情报预报规范》或 SL 250-2000 |
| early-warning | 《防汛条例》或 SL 224-2019 |
| plan-generation | 《防洪法》第41条或 GB 17621-1998 |
| simulation | GB 50201-2014《防洪标准》或《三岔水库调度规程》 |

#### 3. 参数引用
- 汛限水位、安全泄量等约束值来自 `full_context`/`config` 字段
- 未出现硬编码参考值（如 462.0m、460.0m）

### 过时规范清单（禁止使用）
- ❌ SL 44-93《水文情报预报规范》（已废止）
- ❌ GB 50201-94《防洪标准》（已更新为 2014 版）

### 通过标准
- ✅ 三段顺序不可颠倒
- ✅ 结尾段必须是【校验与依据】
- ✅ 规范引用准确（无过时规范）
- ✅ 参数无硬编码

### 失败处理
- ❌ 三段式缺失或顺序错误：立即打回
- ❌ 出现硬编码参数：立即打回

## Layer 3：业务规则验证 📏

### 目的
验证输出是否符合业务规则和安全约束。

### 验证内容

#### 3.1 水位约束

| 检查项 | 通过标准 | 验证方式 |
|--------|---------|---------|
| 当前水位 | 在合理范围（~450-465m） | 数值范围检查 |
| 距汛限水位 | 计算正确（汛限 - 当前） | 重新计算验证 |
| 超限判断 | "未超限/接近/超限"与实际一致 | 阈值判断 |

#### 3.2 降雨约束

| 检查项 | 通过标准 | 验证方式 |
|--------|---------|---------|
| 降雨量级 | 小雨(<10mm)/中雨(10-25mm)/大雨(25-50mm)/暴雨(>50mm) | 分级匹配 |
| 预见期 | 不超过 72 小时 | 时间差计算 |
| 时序 | 按时间升序排列 | 排序验证 |

#### 3.3 告警约束

| 检查项 | 通过标准 | 验证方式 |
|--------|---------|---------|
| 级别匹配 | 红色/橙色/黄色/蓝色与规则阈值一致 | 对照 `ew_info_rules` |
| 未确认告警 | 必须包含数量和级别分布 | 统计验证 |
| 跨域关联 | 红色/橙色告警必须关联水位+降雨+渗流 | 关键词检查 |

#### 3.4 预案约束

| 检查项 | 通过标准 | 验证方式 |
|--------|---------|---------|
| 三组方案 | A/B/C 方案齐全 | 文本匹配 |
| 下泄量约束 | ≤ 下游安全泄量 | 数值对比 |
| 调度规则 | 引用当前生效规则 | 对照 `dispatch_rules` |

### 通过标准
- ✅ 所有数值在合理范围内
- ✅ 计算逻辑正确
- ✅ 超限判断与实际一致

### 典型盲点
- ⚠️ 判断"未超限"时未考虑安全余量（应保留至少 1m）
- ⚠️ 降雨量级分级错误

## Layer 4：安全约束验证 🛡️

### 目的
验证是否违反水库安全红线，防止发布不安全的内容。

### 验证内容

#### 4.1 水位超限判断

```python
def verify_flood_limit(current_rz, flood_limit):
    ratio = current_rz / flood_limit

    if ratio >= 1.0:
        return {"status": "FAIL", "message": "❌ 超限", "severity": "P0"}
    elif ratio >= 0.95:
        return {"status": "WARNING", "message": "⚠️ 接近", "severity": "P1"}
    else:
        return {"status": "PASS", "message": "✅ 正常", "severity": "P2"}
```

#### 4.2 调度优先级

| 场景 | 正确优先级 |
|------|----------|
| 汛期 + 洪水预报 | 防洪优先 > 综合平衡 > 兴利保供 |
| 非汛期 + 枯水 | 兴利保供 > 综合平衡 > 防洪 |
| 应急情况（红色预警） | 立即启动应急预案 |

### 通过标准
- ✅ 水位未超汛限（<100%）
- ✅ 下泄量未超下游安全泄量
- ✅ 调度优先级与当前场景匹配

### 失败处理
- ❌ 水位超汛限或下泄超限：**立即阻塞发布**，升级人工
- ❌ 调度优先级错误：打回，要求调整

### 典型盲点
- ⚠️ 水位超汛限 0.1m 就判"未超限"
- ⚠️ 汛期推荐"兴利保供"方案（违反防洪优先原则）

## Layer 5：跨域一致性验证 🔗

### 目的
验证多个 skill 之间的数据是否一致，防止数据打架。

### 验证内容

#### 5.1 水位一致性

```python
def verify_water_level_consistency():
    forecast_rz = query_forecast_data("current_water_level")["rz"]
    plan_rz = query_plan_data("current_water_level")["rz"]

    if abs(forecast_rz - plan_rz) > 0.1:
        return {"status": "FAIL", "message": "水位数据不一致"}
    else:
        return {"status": "PASS"}
```

#### 5.2 汛限一致性

```python
def verify_flood_limit_consistency():
    forecast_limit = query_forecast_data("flood_limit")["value"]
    warning_limit = query_early_warning_data("flood_limit")["value"]

    if forecast_limit != warning_limit:
        return {"status": "FAIL", "message": "汛限水位不一致"}
    else:
        return {"status": "PASS"}
```

### 通过标准
- ✅ 同一数值在多个 skill 中完全一致（误差 <0.1m 或 <1%）
- ✅ 告警级别与预案响应匹配

### 失败处理
- ❌ 若跨域数据不一致：标记为"数据同步错误"，通知 Owner

### 典型盲点
- ⚠️ forecasting 水位 460.23m，plan-generation 水位 460.2m（精度丢失）
