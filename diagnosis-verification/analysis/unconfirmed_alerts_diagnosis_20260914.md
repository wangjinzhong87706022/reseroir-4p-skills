### 关键异常：水位主站 (stcd=3) 数据异常

**stcd=3 的 rz 值呈现规律性振荡**（459.18 ↔ 462.65），而非自然水文过程：

| 日期 | min_rz | max_rz | 说明 |
|------|--------|--------|------|
| 2026-08-03 | 459.180 | 459.182 | 开始单调上升 |
| 2026-08-10 | 459.571 | 459.688 | |
| 2026-08-20 | 461.194 | 461.364 | |
| 2026-08-29 | 462.464 | 462.535 | |
| 2026-08-31 | 462.593 | 462.629 | 接近峰值 |
| **2026-09-01** | **462.630** | **462.648** | **峰值** |
| **2026-09-02** | **459.180** | **462.650** | **突变！从 462→459** |
| 2026-09-03 | 459.237 | 459.643 | 回落 |
| 2026-09-07 | 462.081 | 462.550 | 又回升 |
| **2026-09-08~11** | **459.180** | **462.650** | **每天振荡 459↔462** |
| 2026-09-14 | 459.206 | 460.124 | |

**[事实]** stcd=3 的水位数据从 8 月 3 日起呈单调线性上升（约 0.17m/天），9 月 1 日达峰值 462.65 后突变回落至 459.18，之后每天在 459.18~462.65 之间振荡。
**[推理]** 真实水库水位不可能以 0.17m/天的速率单调上升 29 天，也不可能每天精确振荡。这是 **模拟/测试数据**，不是真实水文监测数据。
**[结论]** stcd=3 当前数据源已切换为模拟数据，无法用于真实预警判断。

- **首次出现**：2026-06-03 16:00（最后一条告警）
- **持续时长**：103 天（至 2026-09-14）
- **完整 traceback**：无（非代码异常，是服务未运行）
- **历史同类问题**：无（首次停摆）

### 异常 2：水位数据源切换（真实 → 模拟）

- **错误类型**：数据问题
- **首次出现**：2026-08-03（stcd=3 开始单调上升）
- **突变点**：2026-09-02（462.65 → 459.18 跳变）
- **规律**：每天 459.18 ↔ 462.65 振荡，振幅 3.47m，周期 1 天

### 异常 3：水位红色预警 value 值异常

- **错误类型**：内部代码缺陷（数据源混用）
- **表现**：6 月 1-3 日的水位红色预警，value 值出现 107~168（非水位值），与真实水位 459~462 不符
- **根因**：告警引擎在 stcd=NULL 旧源断更后，读取了错误的 eq_code（606K215502/606K215201）的指标值，这些值实际是降雨量或流量，不是水位
- **证据**：
  - `alert_val=489.93` 标注为"水位红色预警"但值是 489（真实水位应在 450~470）
  - `alert_val=110~168` 出现在"水位红色预警"中，但 606K 站是雨量站
  - `st_code` 字段与 `eq_code` 不匹配（st=606K2152 但 eq=606K215502）

## Phase 5：根因分析

### 根因 1（P0）：告警引擎服务停摆

```
[事实] ew_info_message 最后一条告警 create_time=2026-06-03 16:00，此后 103 天无任何新告警

[事实] 水位/降雨数据持续入库（stcd=3 最新 9/14 19:00，606K 雨量站最新 9/14 13:00）
[推理] 数据在入库、规则在配置，但告警没有产生 → 告警引擎进程/服务未在运行
[结论] 根因分类：基础设施问题（告警引擎服务自 2026-06-03 起停止运行）
```

### 根因 2（P1）：水位数据源已切换为模拟数据

```
[事实] stcd=3 水位从 8/3 起单调上升 0.17m/天，9/1 达峰值 462.65 后突变
[事实] 9/8~9/11 每天精确振荡 459.18↔462.65（振幅 3.47m）
[事实] 旧源 stcd=NULL (606K215502) 最后数据 2026-05-29 16:55（断更 108 天）
[推理] 真实水文数据不会以恒定速率单调上升或精确周期振荡
[结论] 根因分类：数据问题（stcd=3 当前数据源为模拟/测试数据）
```

### 根因 3（P1）：告警引擎数据源混用（历史问题）

```
[事实] 6 月 1-3 日水位红色预警 value=107~489（非水位值 459~462）
[事实] 告警 eq_code=606K215502/606K215201 但 st_code=606K2155/606K2152（不匹配）
[事实] stcd=NULL 旧源 5/29 断更后，告警引擎仍引用 606K 设备
[推理] 告警引擎在数据源切换后未正确适配，读取了错误设备的指标值
[结论] 根因分类：内部代码缺陷（告警引擎数据源混用，未随数据源切换更新映射）
```

## Phase 7：修复建议

### 短期止血（立即执行，<1 小时）

1. **重启告警引擎服务**
   - 检查告警引擎进程状态（`systemctl status ew-engine` 或对应服务名）
   - 查看引擎日志定位 6/3 停摆原因（OOM？异常退出？依赖服务断开？）
   - 重启后验证：确认新告警能否正常产生

2. **确认水位数据源**
   - 与数据接入团队确认 stcd=3 当前数据源是真实还是模拟
   - 如果是模拟数据，立即切换到真实监测源
   - 如果是真实数据（极不可能），需排查传感器故障

3. **清理历史未确认告警**
   - 601 条未确认告警中，6 月 1-3 日的 ~80 条红色告警是数据源混用产生的虚假告警
   - 建议：将 6/1-6/3 的虚假告警标记为"误报"（message_confirm=1 + 备注原因）
   - 其余 500+ 条历史告警按等级分批确认（红色优先）

### 长期根治（本周内完成）

4. **修复告警引擎数据源映射**
   - 告警引擎的 eq_code → stcd 映射需要与当前实际数据源一致
   - 建议：在告警引擎启动时自动校验数据源可用性，数据源不可用时降级并告警

5. **添加告警引擎心跳监控**
   - 在 `ew_info_message` 表上添加"最后告警时间"监控
   - 超过 24h 无新告警 → 触发运维告警（而非等人工发现）
   - 建议用 `powerelf-early-warning` skill 的阈值引擎实现

6. **水位数据源切换规范**
   - 数据源切换时同步更新告警引擎的 eq_code/st_code 映射
   - 添加数据源切换的变更审批流程
   - 切换后自动运行 24h 告警验证

7. **更新知识库**
   - 将本次诊断结果写入 `state/knowledge-base/root-cause-solutions.yaml`
   - 更新监控规则 `state/infrastructure-config/alert-rules.yaml`
